Engineering Core: How the Allocator Works

Architectural pillars ensuring zero race conditions and transparent pricing

Technical Architecture →
🛡️

1. Concurrency Safety

Uses database row-level locking (with_for_update) in PostgreSQL and atomic conditional updates in SQLite. Enforces a database-level partial unique index (idx_active_slot_booking) preventing double-booking even under intense parallel thread load.

📈

2. Transparent Surge Pricing

Dynamic tariff calculated purely from real database occupancy: (Occupied / Total) × 100. Tiers range from Standard (1.0x) to Peak (2.0x) with anti-gouging caps. Shared calculation code ensures the frontend and backend always match.

🔄

3. Instant Release & Audit

Drivers receive a unique reference code (BKG-YYYYMMDD-XXXXXXXX). Cancelling releases the slot immediately in an atomic transaction and records full audit trail timestamps for administrative oversight.
